# Протокол чата подрядчика ДомКлик

Восстановлен перехватом трафика 12.08.2026 (`recon/capture.mjs`). Официальной документации
нет, всё ниже получено наблюдением — при изменениях на стороне ДомКлик может разъехаться.

Кабинет: `https://homeland-projects.domclick.ru/` (раздел «Построить дом»).
Аккаунт подрядчика: «Авангард Строй», `casId = 34938681`, id в каталоге `324507`.

## Авторизация

Вход через **Sber ID** с OAuth-редиректом и SMS-подтверждением:

```
POST domclick.ru/cas/rest/oauth/sberId/v4/redirect/parameters
GET  id.sber.ru/CSAFront/oauth/authorize
POST id.sber.ru/api/auth/phone/sms/code
```

Пароля недостаточно — при входе с нового профиля браузера приходит SMS-код. Дальше всё
держится на куках сессии. Время жизни кук **не измерено** (см. «Открытые вопросы»).

## Реалтайм: Centrifugo

```
wss://soba.domclick.ru/connection/websocket?cf_protocol_version=v2
```

Сервер Centrifugo 4.0.5, протокол v2. **JWT в кадре `connect` не передаётся** — аутентификация
идёт через connect-прокси по кукам сессии. Подписывать токены не требуется.

Рукопожатие:

```json
{"connect":{"name":"homeland-projects.domclick.ru","version":"2.1.3"},"id":1}
{"id":1,"connect":{"client":"<uuid>","version":"4.0.5","ping":25,"pong":true}}
```

Пустой кадр `{}` — пинг, отвечать таким же. Каналы:

| Канал | Содержимое |
|---|---|
| `auth-chat:individual#<casId>` | **основной**: новые сообщения, обновления комнат |
| `auth-bell-dc-web:individual#<casId>` | уведомления-колокольчик |
| `auth-chat-room:room-<roomId>` | присутствие в комнате |
| `auth-chat-status:room-<roomId>` | статус комнаты |
| `auth-chat-status:user-<casId>` | онлайн/`lastSeen` участника |

`#` — user-limited канал Centrifugo: подписаться может только этот пользователь.

### Пуш нового сообщения

```json
{"push":{"channel":"auth-chat:individual#34938681","pub":{"data":{
  "action":"add",
  "data":{
    "message":{
      "_id":"6a7cd04b3ee93800016f5c97",
      "uuid":"fa21dda8-2bbd-4a16-be63-a6eb905c2dbd",
      "fromCasId":34938681,
      "roomId":"6a7cc615e2d5c9000156b033",
      "message":"тест",
      "time":1786564683234,
      "type":"message"
    },
    "room":{ "members":[…], "tags":[…] }
  }}}}}
```

В одном пуше есть и сообщение, и комната с участниками — за REST на каждое сообщение
ходить не нужно. `action` бывает `add` (новое сообщение) и `update` (прочтения, апдейт
комнаты); `update` игнорируем.

### RPC поверх сокета

```json
{"rpc":{"method":"ChatSetOnline"},"id":4}
→ {"id":4,"rpc":{"data":{"setOnlineEachSeconds":318}}}
```

Дёргать по таймеру с интервалом из ответа (~300 с), иначе подрядчик числится офлайн.
Также встречался `ChatGetStatus` с `{"casId": <id>}`.

## REST

База: `https://ipoteka.domclick.ru/chat/api/v3/`. Параметр `reqid` — случайная строка для
трассировки, необязателен.

**Обязательный заголовок.** Без него любой запрос отвечает
`400 {"data":null,"error":"'X-Service' header is mandatory"}`:

```
X-Service: web/widget/1.0.1/build-number-null
```

Проверено: с куками из профиля и этим заголовком `GET /rooms` отдаёт `200` из обычного
Python-клиента — **браузер в постоянной работе не нужен**.

| Метод | Назначение |
|---|---|
| `GET /state` | состояние чата |
| `GET /folders` | папки |
| `GET /rooms?list=main&limit=50&offset=0` | список комнат |
| `GET /rooms/{roomId}/messages?limit=50&offset=0&mode=reply_on` | история |
| `POST /rooms/{roomId}/messages` | отправка, `201 Created` |

Тело отправки:

```json
{"type":"message","message":"текст","uuid":"<uuid v4, генерирует клиент>"}
```

`uuid` клиентский — это ключ идемпотентности, безопасно ретраить с тем же значением.

## Модель данных

### Участник комнаты

```json
{"casId":26161372,"chatRole":["USER"],"role":"AGENT",
 "displayName":"Якущенко Никита Сергеевич","description":"Клиент","email":""}
```

**Ловушка:** поле `role` перевёрнуто — у клиента там `AGENT`, у подрядчика `CUSTOMER`.
Различать стороны только по `chatRole`: `USER` — клиент, `CONTRACTOR` — мы.
Системный отправитель — `casId = -900` («Домклик»).

Телефона и почты в payload нет: `email` пустой, `name` — пустой объект. Доступно только ФИО.

### Теги комнаты

```
suburban_developer = 324507      id подрядчика в каталоге
client_cas_id      = 26161372    casId клиента
author_id          = 26161372    кто создал комнату
```

Идентификатора проекта среди тегов **нет**. Название проекта присутствует только в тексте
пресета: `Здравствуйте! Хочу получить смету по проекту дома «{Название}»` — вытаскивается
регуляркой.

**У проектных комнат теги есть всегда.** Проверено на всех 374 проектных комнатах аккаунта:
`client_cas_id` определился у 374 из 374. Ранее казалось, что тег есть лишь у половины, —
на самом деле его нет у комнат **других типов** (ипотека, объявления), которые мы всё равно
отфильтровываем. Каскад «тег `client_cas_id` → `author_id` → участник с `chatRole: USER`»
оставлен как страховка на случай изменений на стороне ДомКлик.

## Состав списка комнат

`GET /rooms?list=main` возвращает **все** чаты аккаунта вперемешку: ипотечные, по
объявлениям, по оценке недвижимости и наши проектные. Фильтровать по тегу
`suburban_developer`. Пагинация через `offset`; на 12.08.2026 у аккаунта **374 проектные
комнаты** — примерно 40 из каждых 50 записей.

> **Осторожно с первым запуском.** 374 комнаты — это 374 диалога, если бездумно залить
> историю в Открытую линию. Операторов накроет лавиной, а CRM получит сотни контактов.
> При старте историю переносить **не** нужно: помечаем текущее состояние как «уже
> известное» и передаём в Битрикс только новые сообщения.

Телефона клиента в данных нет нигде: в боевых переписках операторы спрашивают его текстом
(«Пришлите, пожалуйста, номер телефона»).

## Что важно при интеграции

1. **Эхо-петля.** Отправленное нами сообщение возвращается пушем с `fromCasId` нашего
   аккаунта. Без фильтра ответ оператора уедет в Битрикс как клиентский и закрутит цикл.
   Отбрасывать `fromCasId ∈ {34938681, -900}` плюс дедупликация по `_id`/`uuid`.
2. **Повторная доставка.** Канал `recoverable`, при переподключении Centrifugo досылает
   пропущенное — дедупликация обязательна, а не желательна.
3. **Идентификатор клиента.** `casId` стабилен и сквозной по экосистеме Сбера — годится как
   `user.id` для `imconnector.send.messages`. Формат менять нельзя: Битрикс склеивает
   историю именно по нему.

  `recon/capture.mjs` через сутки: если форма входа не появилась — живут.
- Что приходит, когда клиент пишет **не** пресетом, а произвольным текстом через форму
  «задать вопрос подрядчику».
- Есть ли пагинация/лимиты на `GET /rooms` при большом числе комнат.
- Как выглядят вложения (файлы, фото) — в дампе не встречались.
